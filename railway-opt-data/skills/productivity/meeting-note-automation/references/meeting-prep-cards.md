# Meeting Prep Cards

Use this reference when preparing DJ for an upcoming meeting from calendar + meeting notes.

## Core lesson

The product is not a retrieval report, implementation spec, or polished memo format. It is the concise card DJ would actually read before entering the meeting. A bad prep card that sounds informed but guesses the agenda is worse than no prep.

## Required behavior

1. Identify the actual calendar event first:
   - title
   - date/time in ET
   - duration
   - attendees/organizer
   - calendar description/agenda access

2. Check relevant context, but classify evidence quality:
   - confirmed agenda/current note
   - strong match from recent prior notes
   - weak/stale match
   - no useful context

3. Never turn weak/stale note matches into the meeting frame.
   - Example failure: finding an old note mentioning Zaid/Florentina and writing the memo as if today's meeting is about that deal.
   - Correct behavior: say the agenda is not reliably known and give DJ a sharp first question and branches to listen for.

4. Optimize for meeting performance, not source coverage.
   - Ask: "Would DJ be sharper in the meeting after reading this?"
   - If not, say less.

## Preferred output shape

Keep it very short. Omit sections that do not add value.

```markdown
## [time ET] [Meeting title]

**Bottom line:** [what is known / what is uncertain / posture]

**Walk in knowing**
- [1-3 useful facts only; label stale/weak context]

**DJ should**
- [1-3 concrete behaviors, decisions, or questions]

**If nothing else, ask**
"[one sharp opening question]"
```

## Weak-context pattern

If agenda/context is weak, do not fake depth:

```markdown
## [10:45 AM ET] DJ x Sami x Zaid

**Bottom line:** Calendar shows a short Zoom, but the agenda is not available and prior notes do not reliably establish the topic. Use the first minute to identify the outcome, not to assume the deal frame.

**DJ should**
- Ask what decision or outcome they need in the 15 minutes.
- If this is about a specific project, get asset, phase, owner/investor, economics, and next artifact.
- Avoid committing to scope until the actual ask is clear.

**If nothing else, ask**
"What is the decision or outcome we need from this call?"
```

## Anti-patterns

- Producing a system design when the user asks for a meeting prep example.
- Treating source freshness/scoring/provenance as the visible product.
- Overfitting one stale note because it contains an attendee name.
- Inventing or strongly implying an agenda from weak evidence.
- Writing a memo that would steer DJ into the wrong conversation.
